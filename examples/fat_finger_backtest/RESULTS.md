# 回测结果与核心结论

环境：vnpy 4.4.0（本地 fork，editable）+ vnpy_ctastrategy 1.4.1，Python 3.11.15。
数据：NAS TimescaleDB `md.futures_tick`（500ms 快照），本机直连。

## 一、三品种全 Q2 回测（理论上限，rate=slippage=0）

合约：RM601 / MA601 / TA601（各品种非主力远月），区间 2025-04-01 ~ 2025-06-30。

| 品种 | 合约 | 交易日 | tick 数 | 挂单 | 成交 | 净盈亏 |
|---|---|---:|---:|---:|---:|---:|
| RM | RM601 | 57 | 195,960 | 65 | 0 | 0 |
| MA | MA601 | 57 | 325,573 | 70 | 0 | 0 |
| TA | TA601 | 57 | 488,489 | 84 | 0 | 0 |

**零成交。** 100 万+ tick 回放、挂单逻辑正确触发 200+ 次，但这 3 个月这 3 个远月合约上
没有把价格瞬间砸到 mid 下方 4% 的乌龙。这与方案「悲观场景年触发 0-1 次」一致——**乌龙稀缺
本身就是结论**，不是策略或链路故障（状态机已由单元测试全覆盖）。

## 二、核心发现：撮合口径决定能否捕捉乌龙

为验证「真有乌龙时能否捕捉」，取 fat-finger 已检测的 6 个真实历史乌龙日（RM/MA/TA 非主力、
下砸 4.1-4.5%、单日 1-3 事件的孤立瞬间乌龙），用两种撮合口径各跑一次单日回测：

| 合约 | 事件日 | 均价偏离 | vnpy 官方 ask1 口径<br>挂/成/盈亏 | fat-finger avg_fill 口径<br>挂/成/盈亏 |
|---|---|---:|---:|---:|
| TA2508 | 2025-05-12 | -4.46% | 1 / **0** / 0 | 7 / 2 / +3075 |
| MA2508 | 2025-06-13 | -4.37% | 2 / **0** / 0 | 14 / 2 / +2396 |
| RM2501 | 2024-11-07 | -4.25% | 2 / **0** / 0 | 5 / 2 / +2264 |
| RM2509 | 2025-08-12 | -4.20% | 5 / **0** / 0 | 10 / 3 / +4690 |
| MA2307 | 2023-05-26 | -4.19% | 4 / **0** / 0 | 5 / 1 / +864 |
| TA2509 | 2025-04-10 | -4.10% | 2 / **0** / 0 | 4 / 1 / +882 |

- **vnpy 官方 `ask1` 撮合：6/6 全部漏掉。**
- **fat-finger `avg_fill` 口径：6/6 全部捕捉**，单笔净盈利 ~800-1600 元，符合方案
  「单次净收益 300-1500 元」的中性预期。

### 为什么官方 ask1 口径全漏？数据铁证（TA2509 2025-04-10）

| 量 | 值 |
|---|---|
| 乌龙时刻 | 2025-04-09 21:08:46（夜盘） |
| 事件前 mid | 4323 |
| 策略挂单价 mid×0.96 | 4150.1 |
| fat-finger 反推成交均价 avg_fill | **4147.7**（< 挂单价 → 应触发） |
| 当日 tick 快照最低 ask1 / last | **4288 / 4286**（仅 mid 下方 0.8%） |
| ask1 跌破挂单价的 tick 数 | **0** |

那笔砸到 4147 的成交发生在两次 500ms 快照之间——`turnover` 累计了它（avg_fill 反推得到），
但 **`ask_price1` / `last_price` 盘口快照字段彻底抹平了它**。这正是 fat-finger 的核心约束
「500ms 快照无法还原单笔极价」。**vnpy 官方撮合只看盘口快照字段，故在 500ms 数据上系统性漏报乌龙。**

## 三、avg_fill 口径必须配健全性防线

裸用「每帧 turnover/volume 增量反推 avg_fill」会引入大量伪信号（曾算出单日 6.9 万的虚高盈亏）：

- `turnover` 负增量（数据瑕疵）；
- 盘口过滤造成 tick 不连续，增量横跨大间隔/大宗成交；
- avg_fill 低于跌停板等物理不可能值。

实现中加了三道防线（对齐 fat-finger）后盈亏回归合理：`d_turnover>0` 且 `d_volume>0`、
相邻 tick 间隔 ≤ 10s、avg_fill ≥ 当日跌停价。即便如此，这仍是 fat-finger 七道防线的子集，
**严格的乌龙判定应消费 fat-finger 已检测的事件，而非在 vnpy 侧重算。**

## 四、组合层风控验证（vnpy 单 symbol 测不出的部分）

把 fat-finger 检测的 23 个可捕捉乌龙（RM/MA/TA/FG，下砸 4-8% 孤立瞬间，2023-2026）逐日跑
avg_fill 口径回测，按品种配对后用 `portfolio_merge` 套用「同时最多 1 持仓 + 单日组合亏损 1000 即停」：

| 口径 | 结果 |
|---|---|
| 单品种独立 | 捕捉 20/23 事件，31 成交对，总盈亏 **45,471 元** |
| 组合层裁剪 | 接受 30 笔，**因「已有持仓」拒绝 1 笔**（2023-08-21 夜盘多个 FG 同时乌龙，只吃 1 个），组合净盈亏 **44,187 元** |

- 单笔约 1,467 元（FG 偏离 5% × 乘数 20），量级合理；3 年 23 个可捕捉乌龙 ≈ 年均 7-8 个，
  年化几千~1 万元（3 万本金），落在方案「中性 2-8%」预期。
- 「最多 1 持仓」在真实同日重叠乌龙上确实裁剪；「单日 1000 闸」真实数据未触发（捕捉的多为
  抄底回归盈利），由 `tests/test_portfolio_merge.py` 构造场景单测覆盖两分支。
- 复现：`python portfolio_demo.py`（事件清单 `umbrella_events.json` 由 fat-finger 侧导出）。

> 仍是理论上限：avg_fill 口径假设挂 1 手即成交于均价；23 个事件是 fat-finger 事后检测的真乌龙，
> 实盘要实时排队、打 3-5 折。

## 五、结论与建议

1. **vnpy 的真正价值在「执行纪律的时间驱动回放」**：开盘锚点、漂移重挂、收盘撤单、成交后
   30 秒平仓/止损、单笔/单日止损、冷却——这些 fat-finger 事件回测做不到的，已在本系统逐 tick 验证，
   且策略代码（`FatFingerStrategy`）可平滑接 CTP 实盘。
2. **「成交真实性」上 vnpy 官方 ask1 口径不可用于乌龙指**，必须切到 avg_fill 口径
   （本系统 `fill_proxy=True`）才能捕捉，且仍是理论上限。
3. **推荐分工**：用 fat-finger 事件回测（带七道防线）判定「哪里有乌龙、理论收益多少」；
   用本 vnpy 系统验证「执行纪律在逐 tick 流上是否正确、为实盘铺路」。两者互补，不互相替代。
4. **实盘仍需打 3-5 折**：队列优先级、撤单延迟、部分成交、保证金/滑点均未计入，「排得到队」是独立前提。
